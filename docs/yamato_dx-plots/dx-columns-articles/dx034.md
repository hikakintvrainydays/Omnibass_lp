# 顧客管理(CRM)を始める|まずスプレッドシートから抜け出す

中小企業の顧客管理は、Excelやスプレッドシートでの台帳管理から始まることが多く、規模が大きくなるにつれて「営業担当者ごとに別ファイルがある」「最新版がどれか分からない」「退職時に履歴が引き継げない」といった課題が出てきます。本稿では、中小企業がCRM(Customer Relationship Management)を始める際の論点を、SalesforceやHubSpotなどCRM製品の公式情報を踏まえて整理します。

## スプレッドシートCRMの限界

スプレッドシートで顧客管理を始める利点は、低コストで誰でも触れることです。一方で、規模が大きくなると次のような限界が見えてきます。

- 同時編集での衝突・上書きが起こる
- 担当者ごとにフォーマットが違い、集計に手間がかかる
- 顧客と案件と接点履歴が別ファイルに散る
- 退職・異動時に過去のやり取りが引き継げない
- 検索性・履歴性が弱く、過去の経緯が追えない
- アクセス制御が甘く、機密情報が外部共有リスクにさらされる

「Excel/スプレッドシートで足りる」状態から「CRMが必要」状態に移行するタイミングは、概ね「営業担当が複数になった」「過去の接点履歴を見返したい」「マーケと営業の連携を強めたい」といったときです。

## CRM導入で何が変わるか

CRMは単なる顧客台帳ではなく、「顧客との関係をデータで管理し、営業・マーケ・サポートをつなぐ」ための仕組みです。Salesforceの中小企業向けカスタマーストーリーやHubSpot公式サイトの説明をふまえると、CRM導入で期待できる変化は次のようなものです。

- 顧客ごとに過去の連絡・打ち合わせ・購入履歴・対応履歴が一元化される
- 案件・商談がパイプラインとして見え、進捗を共有できる
- 担当者が変わってもこれまでの経緯が引き継げる
- マーケの問い合わせ獲得から営業の商談化まで連携できる
- レポート機能で売上見込みや活動量を可視化できる

「営業担当の頭の中にある情報」を組織のデータに変えることが、CRMの本質的な目的と言えます。

## 機能要件の整理

CRMは多機能であるがゆえに、導入時に「何のために入れるか」が曖昧だと使われない仕組みになりがちです。中小企業がCRM選定前に整理しておきたい機能要件は次のようなものです。

- 顧客・取引先・担当者の管理(法人と個人を分ける必要があるか)
- 案件・商談管理(パイプライン管理が必要か)
- 接点履歴(メール・電話・訪問・Web行動などをどこまで記録するか)
- メール配信・マーケ機能(リードナーチャリングを行うか)
- 問い合わせフォーム・サポート機能との連携
- カレンダー・タスク連携
- 既存の会計・販売管理システムとの連携
- スマホ対応(外回り営業の入力)
- アクセス権・部門別の閲覧制御

これらを「必要・あれば嬉しい・不要」の3段階で整理しておくと、製品比較がスムーズになります。

## 代表的なCRM製品の方向性

中小企業でよく検討される代表的なCRM製品の方向性を、公式情報を基に整理します。

- Salesforce: クラウドCRMの代表格。中小企業向けに「Starter Suite」など導入しやすいプランが提供されている。Salesforce公式の中小企業向けカスタマーストーリーでは、製造業・サービス業など多くの業種で営業・サービス業務の一元化が進められている事例が紹介されている。
- HubSpot: マーケティング・セールス・サービス・CMSを一体提供するクラウドサービス。HubSpot公式サイトでは、無料CRMから始められる構成と、Marketing/Sales/Service Hubの有料プランが整理されている。
- kintoneでの簡易CRM: kintone上に顧客アプリ・案件アプリを構築し、軽量なCRMとして使う方法。サイボウズの公開事例ページでも顧客管理用途での活用が紹介されている。
- 国内SFA(eセールスマネージャー、Sansan、Mazrica等): 名刺管理や日本企業の営業文化に寄せた製品も選択肢になる。

「Salesforceに入れれば全部解決」ではなく、自社の営業スタイル・予算・既存ITとの相性で選ぶ必要があります。

## 移行手順の基本

スプレッドシートからCRMへの移行を成功させるには、データ移行と運用設計の両方を計画的に進める必要があります。

1. 現状のスプレッドシートを棚卸しし、何を移行し、何を捨てるかを決める
2. CRM側のデータ項目を設計する(顧客・取引先・担当者・案件・接点履歴の関係)
3. CSVなどで初期データを移行する(重複と表記ゆれを掃除する)
4. 入力ルール・ステージ定義(商談ステータスの段階)を決める
5. 一部の営業チームでパイロット運用し、改善する
6. 全社展開し、レポート・KPIに組み込む

最初の数か月はスプレッドシートとCRMの並行運用が発生しがちですが、二重入力が長く続くと現場が疲弊するため、早めにCRM側へ切り替える計画が必要です。

## 定着のためのポイント

CRMの最大の難所は「営業担当が入力してくれない」問題です。この対策として効果的なのは次のような取り組みです。

- 入力項目を最小限に絞る(必須は5項目程度から始める)
- スマホ・名刺アプリ・メール連携で入力負荷を下げる
- 営業会議の資料をCRMで作る(=入力していないと議論できない状態にする)
- 経営層がCRMをそのまま閲覧する文化にする
- KPIや評価制度との接続を段階的に行う(最初から評価に紐付けると形骸化する)

「ツールが良ければ定着する」のではなく、「定着する仕組みと文化を作るために、ツールを使う」という順序で考えるのが現実的です。

## CRMは「顧客との関係を資産化する」投資

中小企業のCRM導入は、短期的な営業効率化だけでなく、中長期で「顧客との関係を組織の資産にする」ための投資です。スプレッドシートからCRMへの移行は、単なるツール置き換えではなく、営業プロセスを見直す機会と位置づけて取り組むのが現実的です。
