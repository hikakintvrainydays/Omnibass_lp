# プロンプトインジェクション対策|生成AI利用企業のチェックリスト

業務で生成AIを使う企業が増えるにつれ、「プロンプトインジェクション」という攻撃手法への関心が高まっています。これは生成AI特有のリスクで、従来のWebアプリケーション脆弱性とは異なる性質を持ちます。本記事では、IPAや総務省・経済産業省の公開資料を踏まえ、プロンプトインジェクションの仕組みと、企業が運用面で確認すべきチェックポイントを整理します。

## プロンプトインジェクションとは

プロンプトインジェクションは、生成AIに対する入力(プロンプト)を悪意ある形で操作し、本来意図されていない動作・出力を引き出す攻撃の総称です。代表的な分類として次のような考え方が知られています。

- 直接型(ユーザーが直接、悪意あるプロンプトを送る)
- 間接型(AIが読み込む外部コンテンツやファイルに、攻撃者が仕込んだ命令が含まれる)

特に間接型は、Webページ要約・メール要約・社内ドキュメント検索など、AIが「人間以外の入力」を扱う場面で発生しやすく、利用者本人に攻撃を受けている自覚がないケースが多いのが特徴です。

IPA「情報セキュリティ10大脅威」でもAI関連の脅威が継続的に取り上げられており、生成AIの普及に伴い注目度が高まっています。最新の脅威動向は公式ページで確認することを推奨します。

## 想定される業務上のリスク

プロンプトインジェクションが業務システムで成功した場合、次のような影響が考えられます。

- 機密情報・個人情報の漏洩(AIに与えた情報が攻撃者に向けて出力される)
- 不正な操作の実行(AIエージェントに連携された機能の悪用)
- 不正確・誘導的な情報の出力(社内意思決定への影響)
- 外部サービス連携の悪用(メール送信、データ書き換え 等)
- フィッシングメール・偽情報の自動生成への加担

特にAIに「行動権限」(メール送信、ファイル操作、API呼び出しなど)を持たせた構成では、影響範囲が一気に広がるため、設計段階での検討が不可欠です。

## 対策の4つの基本軸

プロンプトインジェクション対策は単一の技術で解決するのではなく、複数の層で対応する考え方が一般的です。基本的な4軸を整理します。

### 1. 入力の検証・サニタイズ

- 外部から取り込むテキスト(Webページ、メール、ファイル)を「信頼できない入力」として扱う
- 命令の形に見える文字列の検出やラベリング
- 大量入力・隠し文字・特殊エンコードの検査

### 2. 出力の検証

- 機密情報を含む出力のフィルタリング
- 想定外のリンク・スクリプト・コマンドの除去
- 重要操作の前にユーザー確認を挟む設計

### 3. 権限の分離

- AIエージェントに与える権限を業務単位で最小化
- 重要操作(送金、削除、外部送信)は人間の承認を必須化
- 取り扱う情報のクラス分けと、アクセス可能なAIの限定

### 4. 監視・ログ

- 入力・出力・操作履歴のログ取得
- 異常パターンの検知ルール
- インシデント発生時の調査手順と保管期間

これらを単独で導入するのではなく、組み合わせて「層」を作ることが重要です。

## 運用チェックリスト(例)

実務で利用しやすい確認項目の例を示します。自社サービス・利用ツールの状況に合わせて取捨選択してください。

### サービス選定時

- 提供事業者の利用規約・データ取扱い・セキュリティ説明を確認したか
- 入力データが学習に使用されるか・無効化できるか
- 監査ログ・操作履歴の取得可否
- インシデント対応窓口・SLAの記載
- 国内外のガイドライン(AI事業者ガイドライン等)への適合状況

### 設計・実装時

- 外部入力(Web/メール/ファイル)を「信頼できない入力」として扱っているか
- 機密データのカテゴリと、それを扱うAIの分離
- 重要操作はユーザー確認を経由しているか
- システムプロンプトと外部入力を区別する仕組みがあるか
- 出力を業務システムに直接流す前にチェックを入れているか

### 運用時

- 利用者向けのガイドライン(入力していい情報・していけない情報)
- 異常時の連絡フロー(担当者・社外の相談先)
- ログの定期レビュー
- 新たな攻撃手法・脆弱性情報のキャッチアップ体制
- 半年〜1年に1回の利用ルール・対策の見直し

このチェックリスト自体を社内文書として整備し、利用部門・情報システム部門・経営層で共有しておくと、判断のずれを防ぎやすくなります。

## ガイドラインとの関係

プロンプトインジェクション対策は単独のテーマではなく、AIガバナンス全体の一部です。経済産業省・総務省「AI事業者ガイドライン」では、AI利用者の責任や安全性に関する考え方が整理されており、社内ルールの背景情報として参照できます。総務省のAI関連ガイドライン情報や、IPAの脅威・対策情報も併せて確認することで、技術面と運用面の両輪で整理しやすくなります。

## 利用者教育で押さえたいポイント

技術的対策と並行して、利用者教育も欠かせません。次のような内容を社内研修・利用ガイドに含めることを推奨します。

- 生成AIに入力してはいけない情報の例(個人情報、機密情報、契約情報 等)
- 外部のWebページ・PDF・メール内容をAIに読ませる際の注意点
- AIから返ってきた指示・URL・コードを鵜呑みにしないこと
- 不審な挙動・出力があった場合の報告先
- 利用するAIサービスの最新の利用規約変更への注意

「禁止事項を並べる」よりも、「なぜ問題になるのか」を具体例とともに伝える方が、現場の理解を得やすくなります。

## まとめ:層で守り、運用で支える

プロンプトインジェクション対策は、銀の弾丸ではなく多層防御と運用改善の組み合わせで実現する性質のテーマです。入力検証・出力検証・権限分離・監視という4つの軸を組み合わせ、AI事業者ガイドラインや10大脅威の動向を踏まえて見直しを続けていくことが、生成AI活用と安全性の両立につながります。
