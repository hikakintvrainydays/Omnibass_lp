# Zapier / Make / Power Automate どれを使う?用途別比較

クラウドサービス(SaaS)同士を連携させる業務自動化ツール、いわゆるiPaaSの代表格として挙げられるのがZapier、Make、Microsoft Power Automateの3つです。「フォーム送信をトリガーにチャット通知」「メール受信をトリガーに台帳登録」といった日常的な自動化を、コードを書かずに作れます。本稿では3つのサービスの位置づけ、料金体系、対応サービス数、日本企業での選び方を整理します。

## 3サービスの位置づけ

3サービスはいずれも「クラウドサービスをトリガーで起動し、別のサービスに連携処理を行う」点で共通していますが、出自と狙う領域が異なります。

**Zapier**
米国発のiPaaS老舗で、サービスの「コネクタ数(連携先数)」の多さで知られます。Zapier公式サイト(https://zapier.com/)では、対応アプリ数や事例、料金プランが網羅的に公開されています。シンプルなトリガー&アクションを直感的なUIで組み合わせるスタイルで、非エンジニアにも扱いやすいのが特徴です。

**Make(旧Integromat)**
チェコ発のiPaaSで、ビジュアルなフローエディタと柔軟なデータ加工処理が強みです。Make公式サイト(https://www.make.com/)で機能・料金・テンプレートが公開されています。条件分岐・ループ・JSON操作などを視覚的に組めるため、複雑なフローを作りたいケースに向いています。

**Microsoft Power Automate**
Microsoftが提供するiPaaSで、Microsoft 365との親和性が大きな特徴です。Microsoft公式ドキュメントによれば、クラウドフロー(SaaS連携)とデスクトップフロー(RPA)の両方を扱える点が他2社との大きな違いです。

## 料金体系の考え方

各サービスとも、料金は「実行回数」「シナリオ数」「ユーザー数」「使える機能の幅」で決まる仕組みになっており、いずれも公式サイトで最新の料金を公開しています(各サービス公式参照)。料金を比較するときは表面のサブスク額だけでなく、次の観点で見ることが重要です。

- 月間実行回数(タスク数 / オペレーション数)の上限
- 実行間隔の最小値(無料/下位プランは数分間隔のみのケースあり)
- プレミアムコネクタ・有償コネクタの有無
- 同時実行・履歴保管期間の制限
- ユーザー単位課金か、組織単位課金か

「無料プランで試して、有償プランに上げる」シナリオが各社共通で使えるため、まずは無料プランで実フローを組んでから判断するのが安全です。

## 対応サービス数とコネクタの違い

3サービスとも数千の外部サービスに対応していますが、傾向が異なります。

- **Zapier**: 連携アプリ数の網羅性が高く、ニッチなSaaSにも対応していることが多い
- **Make**: 連携数も多いうえ、HTTP/Webhookやデータ加工モジュールでカスタム連携を作りやすい
- **Power Automate**: Microsoft 365・Dynamics 365・Azureなどマイクロソフト製品との連携が圧倒的に強く、エンタープライズ向けプレミアムコネクタも豊富

業務に必要な「連携先」が決まっている場合、各社の公式コネクタ一覧で対応状況を確認するのが最も確実です(Zapier公式、Make公式、Microsoft Power Automate公式参照)。

## 日本企業で選ぶときの判断軸

日本の中小企業がiPaaSを選ぶときには、機能・料金以外にも次の観点が効いてきます。

**1. UI・ドキュメントの日本語対応**
Power Automateは日本語UI・日本語ドキュメントが充実しています。Zapier・Makeも日本語対応は進んでいますが、最新機能や事例情報は英語先行のことも多いため、社内のリテラシーに応じて判断します。

**2. 既存ライセンスとの相乗り**
Microsoft 365を導入済みであれば、Power Automateの一部機能を追加コストなく使えるケースがあります。総コストの観点で、既存ライセンスとの相乗り余地を確認することが重要です。

**3. 将来的なRPA展開**
画面操作の自動化(デスクトップRPA)も視野に入れる場合、クラウドフローとデスクトップフローを同一プラットフォームで扱えるPower Automateが有利です。

**4. 海外SaaS中心か日本SaaS中心か**
Zapier・Makeは海外SaaS連携の蓄積が厚く、Power Automateは日本でもMicrosoftエコシステム連携で選ばれやすい傾向にあります。

## 用途別マッピング

実装したい業務シナリオから、サービスを選ぶ際の目安は次のとおりです。

- 海外SaaS同士のシンプルな連携 → Zapier
- 複雑な条件分岐・データ変換を伴う連携 → Make
- Microsoft 365中心の業務連携 → Power Automate(クラウドフロー)
- 古い社内システムへの画面操作も含めて自動化したい → Power Automate(デスクトップフロー)
- 全社的な業務自動化基盤として一貫運用したい → Power Automate

ただしこれは目安であり、実際は試作を通じて使用感を比較することが推奨されます。

## 試すときのおすすめステップ

iPaaSの選定で失敗を減らすためには、次のようなステップで試すのが現実的です。

1. 現在の業務で「自動化候補」を3〜5本ピックアップする
2. 各サービスの無料プランで、もっとも頻度の高い1本を実装してみる
3. 同じシナリオを別サービスでも組み、UI・トリガー・実行履歴を比較する
4. 月間実行回数を見積もり、有償プラン移行時のコストを試算する
5. 運用担当・引き継ぎ体制を考慮して最終的に1社に絞る

「同じ業務を3社で組む」と、どのサービスが自社の感覚に合うかが体感できます。

## 内製と外注の境界線

iPaaSは「ノーコードで誰でも作れる」と紹介されがちですが、実務では条件分岐・エラー処理・例外対応の設計が品質を左右します。社内で内製する場合は「定型シナリオを作る人」と「設計レビューする人」を分けるのが理想です。エラー時に業務が止まる重要なフローは、運用設計まで含めて外部の専門家に相談したうえで、ステップアップしながら内製範囲を広げる進め方が安全です。
