# クラウドサービスのセキュリティ評価|中小企業の選定基準

クラウドサービス(SaaS、IaaS、PaaS)を業務で利用するのは、中小企業にとっても当たり前の選択肢になりました。一方で、利用する事業者・サービスのセキュリティ水準を評価し、契約や運用に落とし込む作業は、専任担当者がいない企業ほど負担が大きくなりがちです。本記事では、総務省「クラウドサービスの安全・信頼性に係る情報開示指針」などを参考に、中小企業の現実的な選定基準を整理します。

## クラウド利用のメリットと評価の必要性

クラウドサービスは、自社で機器を保有せずに業務システムを利用できる点で、コスト・運用負荷の観点で多くのメリットがあります。一方、データの保管場所や運用主体が変わることで、新たに考慮すべき観点も生まれます。

- データの所在(国内/海外、データセンター)
- セキュリティ対策の責任分界(事業者と利用者)
- インシデント発生時の通知・対応
- サービス停止・撤退時のデータ取り扱い
- 法令・契約上の制約(個人情報保護、業界ガイドライン)

クラウドの特性を踏まえずに導入してしまうと、「便利だが、いざというときに何も分からない」という状態に陥りやすいため、選定段階での評価が重要になります。

クラウドサービスのセキュリティ評価を考えるうえで、公的に参照できる資料がいくつかあります。

- 総務省「クラウドサービスの安全・信頼性に係る情報開示指針」関連ページ

## 中小企業向けの選定軸

クラウドサービスを評価する際の主な軸を整理します。

### 1. 事業者・運営体制

- 運営会社の所在・体制(国内法人か、海外法人の支店か など)
- セキュリティ専任体制の有無
- ISMS(ISO/IEC 27001)、ISO 27017、SOC 2、ISMAP 等の第三者認証
- 公開されているセキュリティホワイトペーパーや透明性レポート

### 2. データ取扱い

- データの保管場所(国・リージョン)
- 暗号化(保存時、通信時、鍵管理)
- バックアップの取得・復元の仕組み
- 個人情報・特定情報の扱いに関する記述
- 学習・分析利用の有無と無効化可否(AI機能を含むサービスの場合)

### 3. アクセス制御・運用

- 多要素認証(MFA)の対応
- 権限管理(ロール、グループ)
- 監査ログ・操作ログの取得とエクスポート
- 不正アクセス検知・通知の仕組み
- API利用時のセキュリティ(トークン管理、IP制限 等)

### 4. 可用性・障害対応

- SLA(稼働率、サービスクレジット)
- 障害発生時の通知ルート・所要時間
- 計画停止・メンテナンスの予告
- 障害履歴の公開状況

### 5. 契約・終了時の取り扱い

- 契約期間、解約条件
- データのエクスポート可否・形式
- 契約終了時のデータ削除タイミングと証跡
- 海外での裁判管轄・準拠法

これらを「すべて満たす」サービスを探すのではなく、自社が扱う情報の重要度に応じて優先度を設定することが現実的です。

## 「責任共有モデル」の理解

クラウドサービスのセキュリティでは、事業者と利用者の責任分界を理解することが基本です。一般的に次のような切り分けが用いられます。

- IaaS:インフラの物理・基本的な仮想化部分は事業者、OSから上のセキュリティは利用者
- PaaS:プラットフォーム部分まで事業者、アプリ・データは利用者
- SaaS:アプリケーション全体は事業者、利用者側はアカウント・権限・データ管理など

「クラウドにしたから安全」ではなく、利用者側で責任を負う領域(主にアカウント、設定、利用方法)を理解し、適切に運用することが必要です。

## ありがちなクラウド利用の落とし穴

中小企業で実際に問題になりやすい運用上の課題を挙げます。

- 共有フォルダ・ドキュメントが「リンクを知っている人全員」公開になっている
- 退職者のアカウントが残ったまま外部から利用できる状態
- 外部連携アプリ(OAuth)に過剰な権限を付与している
- 管理者アカウントがMFA未設定
- 一括ダウンロード時のログが取得されていない
- バックアップが「クラウド任せ」で、自社からエクスポートできていない
- 契約終了時のデータ削除証跡を残していない

これらは技術ではなく運用の問題で、定期的な棚卸しと社内ルールでカバーする必要があります。

## 契約・調達時に確認したいポイント

利用部門だけで導入を進めず、調達・法務・情報システム部門が関与する流れを作ることも重要です。最低限、契約・調達段階で次の点を確認することを推奨します。

- 自社の機密情報・個人情報を扱うかの判定
- 取扱いに必要なセキュリティ要件(認証、暗号化など)を明文化
- 利用規約・データ処理に関する条項の確認
- 障害・インシデント発生時の通知義務、SLA
- データ所在・移転に関する制約
- 解約時のデータ取り扱い

業界によっては別途、業界ガイドラインや顧客の個別要求が加わるため、自社が属する業界の動向も併せて確認するとよいでしょう。

## 退去時(契約終了時)のデータ

意外と見落とされがちなのが、契約終了時のデータ取り扱いです。次の点を事前に確認しておくと、移行や解約がスムーズになります。

- データのエクスポート方法・形式・保管期間
- 契約終了後の自動削除タイミング
- 削除完了の証跡(削除証明書など)を発行できるか
- バックアップ・ログの削除範囲

これらは契約段階で確認しないと、実際に解約する際に思わぬコストや時間がかかることがあります。

## まとめ:評価軸を持って継続的に見直す

クラウドサービスのセキュリティ評価は、一度きりの作業ではなく、利用開始後も継続的に見直していく性質のテーマです。総務省・経済産業省の関連資料を参考に、自社の業務と情報の重要度に合わせた評価軸を持ち、選定・運用・終了の各フェーズで点検することで、クラウド活用と安全性の両立がしやすくなります。
