# サプライチェーン攻撃|中小企業が標的になる理由と対策

サプライチェーン攻撃は、ここ数年で経営課題として急速に注目されるようになったサイバー脅威の一つです。直接の標的が大企業や公共機関であっても、その入口として中小の取引先・委託先・ソフトウェアベンダーが狙われるケースが増えています。本記事では、IPAや経済産業省が公表する公式ガイドラインを手がかりに、攻撃の構図と中小企業が取れる対策を整理します。

## サプライチェーン攻撃とは何か

サプライチェーン攻撃は、最終的な標的(大企業、官公庁、重要インフラなど)に侵入するために、その「サプライチェーン」を構成する企業・サービス・ソフトウェアを経由して攻撃する手法の総称です。代表的な攻撃経路には次のようなものがあります。

- 委託先・取引先のネットワーク経由でのアクセス
- 共有アカウント・VPN・専用線の悪用
- ソフトウェア更新プロセスやアップデートサーバへの不正介在
- 開発委託先のソースコード・認証情報の窃取
- クラウドサービス側の脆弱性・不適切設定の悪用

IPA「情報セキュリティ10大脅威」では、組織編で「サプライチェーンの弱点を悪用した攻撃」が長年高い順位で取り上げられており、企業規模を問わず関係者全体での対策が求められるテーマとして整理されています。

## なぜ中小企業が狙われるのか

中小企業がサプライチェーン攻撃の入口になりやすい背景には、構造的な要因があります。

- 大企業に比べてセキュリティ専任者・予算が限られる
- 大企業システムへのアクセス権限を持つ場合がある
- ソフトウェア・サービス提供者として広いユーザーに影響を与えうる
- 子会社・関連会社・地方拠点として大企業と同じ業務システムを利用していることがある
- セキュリティ対策状況の可視化が難しく、攻撃検知が遅れやすい

つまり「自社が攻撃の最終標的でない」場合でも、取引先・親会社にとってのリスクとなり、攻撃者から見れば狙う価値のある入口になります。

## 取引先・親会社からの要求が増えている

経済産業省「サイバーセキュリティ経営ガイドライン」では、経営者が認識すべき重要項目の一つとして、ビジネスパートナーや委託先を含めたサプライチェーン全体のセキュリティ対策が示されています。これに伴い、近年は次のような取引先要求が増えています。

- セキュリティチェックシートへの回答(年1回など)
- ISMS(ISO/IEC 27001)など第三者認証の取得状況の提示
- インシデント発生時の報告ルートと所要時間の明記
- 委託先・再委託先の管理状況の説明
- アクセス権限管理・ログ取得状況の説明

これらは「契約上の前提」として扱われ始めており、回答できないと取引機会を失うリスクもあります。

## 中小企業向け対策フレーム

サプライチェーン攻撃への対策は、自社単独ではなく「自社↔取引先↔顧客」の3者関係で考える必要があります。実務的な整理軸として次のようなフレームが有効です。

### 1. 自社内部の対策

- アカウント・権限の最小化(特に他社接続用アカウント)
- 多要素認証(MFA)の徹底
- VPN・リモートアクセスの利用範囲と認証強化
- エンドポイント対策・更新管理・ログ収集
- 重要データのバックアップとオフライン保管

### 2. 委託先・取引先に対する管理

- 契約書へのセキュリティ条項(再委託、報告義務、監査権)
- セキュリティチェックシートの運用と回答内容の確認
- 委託先で扱う情報範囲の最小化
- 委託先のインシデント発生時の連絡ルート整備

### 3. 自社が「委託先側」のときの備え

- 顧客・親会社向けに説明できる対策一覧の準備
- 第三者認証(ISMS等)や自己宣言制度の活用
- 監査・ヒアリング対応の窓口と回答テンプレート
- インシデント発生時の報告所要時間と内容の事前合意

これら3つを行き来しながら整備していくことで、サプライチェーンの両側からの要求に応えやすくなります。

## ソフトウェア依存と「見えない」サプライチェーン

サプライチェーン攻撃の難しさは、人と契約だけでなく、利用ソフトウェア・OSS(オープンソースソフトウェア)・SaaSなどの「見えない依存関係」にも及ぶ点です。

- 利用ソフトウェアの一覧化(SBOMの整備)
- アップデート・脆弱性情報のウォッチ体制
- 不要なソフトウェア・拡張機能の定期的な棚卸し
- SaaSの設定・権限・連携先アプリの確認
- 終了サービス・EOL製品の早期更新計画

中小企業ではここまで網羅的に管理することは難しい場合もありますが、「重要業務に関わるシステム」だけでも依存関係を整理する価値があります。

## インシデント発生時の連携

サプライチェーン攻撃を完全に防ぐことは難しく、被害が起きた際の連携も重要です。

- 自社で異常を検知した際の取引先への通知判断基準
- 取引先で侵害があった場合の自社内の影響評価手順
- 外部相談先(IPA、警察、専門事業者、契約しているセキュリティ会社)
- 顧客・関係者への説明資料のひな型

平時からこれらを準備しておくことで、有事の意思決定スピードが大きく変わります。

## まとめ:中小企業こそ「点ではなく面」の対策を

サプライチェーン攻撃は、自社単独の対策だけでは防ぎきれない攻撃類型です。IPAの10大脅威で脅威の傾向を把握し、経済産業省「サイバーセキュリティ経営ガイドライン」を経営判断のフレームとして活用しながら、取引先との関係性を含めた「面」での対策に取り組むことが、中小企業の事業継続にとって現実的な解となります。
