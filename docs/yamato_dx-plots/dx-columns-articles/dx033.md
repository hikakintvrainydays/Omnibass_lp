# ノーコードツールで中小企業ができること|限界と使いどころ

ノーコード(No-Code)・ローコード(Low-Code)ツールは、プログラミングをほとんど書かずに業務アプリやワークフローを構築できるサービスの総称です。中小企業の現場でも、kintone、AppSheet、Glide、Microsoft Power Apps、サイボウズ Office、Notion、Airtableなど、用途の異なる複数のサービスが利用されています。本稿では各サービスの公式情報や、IT導入補助金の対象ITツール検索などを参照しつつ、中小企業がノーコードでできること・できないこと、選び方を整理します。

## ノーコードとは何か

ノーコードは、画面操作と設定だけで業務アプリ・ワークフロー・自動化を作れる仕組みを指します。ローコードはコードを少量書く前提のもので、両者を厳密に分けない場合もあります。

代表的な領域としては次のようなものがあります。

- 業務アプリ: kintone、AppSheet、Microsoft Power Apps、Glide、Airtableなど
- 自動化(iPaaS): Zapier、Make、Microsoft Power Automateなど
- グループウェア・社内ポータル: サイボウズ Office、Notion、Microsoft 365、Google Workspaceなど
- フォーム・アンケート: Googleフォーム、Microsoft Forms、Typeformなど
- Webサイト・LP: STUDIO、ペライチ、Wix、Squarespaceなど

中小企業の業務改善でよく登場するのは、業務アプリ系・自動化系・社内ポータル系の3カテゴリです。

## ノーコードで「できること」

中小企業がノーコードで現実的にできることは、おおむね次の範囲です。

- Excel・スプレッドシートで運用していた台帳・案件管理のWebアプリ化
- 紙の申請・点検記録のスマホ入力化
- 受発注・在庫・問い合わせなどの軽量管理アプリ
- 簡単な社内ポータル・社内Wiki・FAQ
- フォーム回答→通知→台帳追加の自動化
- 既存SaaS同士の連携(クラウド会計・チャット・カレンダーなど)

「現場の小さな困りごとを、Excel運用から一段引き上げる」程度であれば、ノーコードで十分にカバーできます。中小企業基盤整備機構が運営するIT導入補助金の対象ITツール検索ページでも、業務改善ツールとしてノーコード系のサービスが多数登録されており、選択肢は年々増えています。

## ノーコードで「できないこと・苦手なこと」

一方で、ノーコードは万能ではありません。中小企業の現場でも次のような領域は、ノーコード単独では難しい・無理が出やすい範囲です。

- 大規模・高頻度のトランザクション処理(秒間多数のリクエストなど)
- 複雑な原価計算・在庫評価などの基幹業務ロジック
- 業界特有の厳密な会計・税務処理
- 数十テーブルを跨ぐ正規化されたDB設計が必要な領域
- ピクセル単位のUI要件・独自のデザインシステム
- 高い性能要件・高度なセキュリティ要件(専用VPC、独自暗号化など)

これらは無理にノーコードで作ると、「動くけれど運用が回らない」「最初は良いがすぐに限界が来る」状態になりがちです。基幹システムや製造の生産管理など重要領域は、パッケージや受託開発との組み合わせが現実的です。

## 代表ツールの方向性

代表的なノーコード業務アプリの方向性を、公式情報を基に整理します。

- kintone(サイボウズ): 中小企業の業務アプリ全般。日本企業の業務に近いテンプレートと、サイボウズおよびパートナーのプラグイン・連携サービスが豊富。
- AppSheet(Google): Googleスプレッドシート・Excel・データベースなどをデータソースに、ブラウザ・モバイルアプリを作れる。Google Workspaceの一部プランに含まれる構成。
- Microsoft Power Apps: Microsoft 365 / Dataverseと組み合わせて使う。Power AutomateやPower BIと一体運用しやすい。
- Glide: Googleスプレッドシートなどから、モバイル中心のアプリをすばやく作るのに向く。
- Airtable: スプレッドシート風UIのデータベースで、リレーションやビュー切替に強い。

これらは「同じノーコード」でもデータモデル、UIの自由度、モバイル対応、外部連携の方向性が異なります。

## 選び方の軸

中小企業がノーコードツールを選ぶ際の軸は、おおむね次の通りです。

- 業務の中心: 帳票・申請・案件管理が中心ならkintone系、モバイル現場入力ならAppSheet/Glide、Microsoft 365中心ならPower Apps、Google Workspace中心ならAppSheet。
- 既存資産: すでに導入しているグループウェア・会計・勤怠との連携実績で選ぶ。
- 利用者像: 情報システム担当が薄く、現場主導で運用するならkintoneやAppSheetなど現場向けが扱いやすい。
- データ量・利用人数: 数百名規模・大量データになると、ノーコード単独ではきつくなる場面が増えるため、外部DBやデータ基盤との連携を前提に検討する。
- 補助金・予算: IT導入補助金の対象ITツールに該当するかも、選定の参考になる。

## 「ノーコードで作る」と「ノーコードで設計する」の違い

ノーコード導入で失敗するパターンの多くは、「ツールが簡単だから業務もそのまま簡単になる」と誤解することです。実際には、業務の整理・データ設計・運用ルール作りは、ノーコードでも従来のシステム開発でも本質的に同じだけ必要です。違うのは「コードを書くか書かないか」の部分だけです。

中小企業でノーコードを活かすには、次のスタンスが現実的です。

- 業務フロー・帳票・データを先に紙やホワイトボードで整理する
- ノーコードはあくまで実装手段として、複数候補を試す
- 「動くか」だけでなく「半年・1年運用できるか」で判断する
- 必要に応じてノーコードと受託開発を組み合わせる

## ノーコードは「中小企業の主戦場」になりやすい

中小企業はIT人材が薄い一方で、業務はベテラン社員のノウハウが詰まっており、パッケージにそのまま当てはまらないケースも多くあります。ノーコードは、自社の業務に合わせた仕組みを比較的短期間で作れる点で、中小企業との相性が良い領域です。「全社一斉に基幹を入れ替える」よりも、「既存システムの周辺を、ノーコードで少しずつ良くしていく」方が現実的に効きやすいパターンが多いと言えます。
